# DGen Progress - 2026-08-17

## Summary

Today the project moved from a rebranded demo toward a usable personal AI creation workbench. The major technical focus was real API readiness, browser persistence hardening, and the first architecture decision for future provider extensibility.

## Completed

### Real API Smoke Readiness

- Confirmed that real model-service credentials can be entered through the credential drawer.
- Confirmed that the model service credential path can reach the API and is ready for text, image, and video workflow testing.
- Identified that the private asset library credential and object-storage credential are separate from the model-service credential. They are only required for asset-library management and cloud-readable reference media flows.

### Browser Persistence Hardening

Commit: `08b0a0f Harden browser persistence for generated media`

What changed:

- Added `src/stores/persistence.ts` as a shared persistence utility.
- Migrated video, video 2.5, and image storage keys:
  - `byteplus-ai-gen-platform-video` -> `dgen-platform-video`
  - `byteplus-ai-gen-platform-video25` -> `dgen-platform-video25`
  - `byteplus-ai-gen-platform-image` -> `dgen-platform-image`
- Kept backward-compatible reads from the old BytePlus keys.
- Removed legacy keys after successful write to the new DGen keys.
- Slimmed persisted history by removing local `data:` and `blob:` URLs.
- Preserved full in-memory generation payloads so generation quality and API requests are not changed.
- Added tests for key migration and large-object filtering.

Why this matters:

- Real video/image testing can produce large local references and task records.
- Browser `sessionStorage` has strict quotas.
- The app should persist task metadata, not large local media payloads.

### Auth And Chat Storage Key Migration

Commit: `cfb9751 Migrate auth and chat storage keys`

What changed:

- Migrated auth and chat storage keys:
  - `byteplus-ai-gen-platform-auth` -> `dgen-platform-auth`
  - `byteplus-ai-gen-platform-chat` -> `dgen-platform-chat`
- Kept backward-compatible reads from old keys.
- Added tests to ensure existing browser sessions can migrate without losing credentials or drafts.

Why this matters:

- Credential storage is still per-tab `sessionStorage`, matching the BYO credential model.
- The app no longer writes new runtime state under the old product name.
